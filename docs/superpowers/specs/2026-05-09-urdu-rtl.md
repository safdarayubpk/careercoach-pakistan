# Phase 9 — Urdu RTL Layout Spec

**Date:** 2026-05-09
**Status:** Approved — ready for implementation

---

## Overview

The app UI is English (LTR). Users can type or dictate answers in Urdu (RTL). Currently all text areas and answer display surfaces are hard-coded LTR — Urdu text appears left-aligned and visually incorrect (letters render RTL but the container is anchored left).

**Goal:** All surfaces that display user-generated text (answer input, voice preview, session report answer replay) correctly render Urdu as right-to-left, right-aligned, with readable Urdu typography. The English UI layout is unchanged.

**Scope:** Content areas only — not a full UI language switch. The app menu, buttons, and labels remain English/LTR.

---

## What "Urdu RTL" means in this app

| Surface | Current | After Phase 9 |
|---------|---------|---------------|
| Answer textarea | LTR, left-aligned | Auto-detects direction — Urdu input is RTL, right-aligned |
| Voice interim preview | LTR | Same auto-detection |
| Session report answer replay | LTR | RTL when Urdu |
| Question text | Already English | No change |
| Feedback score/correct/missing | Already English (AI-generated) | No change |

> Note: `FeedbackView` (`feedback-view.tsx`) does **not** display the user's answer text — it only shows AI-generated content (score, correct/missing points, improve tip, model answer), all in English. No RTL changes needed there.

## Part 1 — Answer Textarea (`answer-form.tsx`)

### Text direction

Add `dir="auto"` to the `<textarea>`. Browsers use the Unicode Bidirectional Algorithm on `dir="auto"`: if the first strongly-directional character is RTL (Arabic/Urdu), the whole block is RTL and right-aligned. If LTR (Latin), it stays LTR. This is the standard spec-compliant approach — no JS required.

```tsx
<textarea
  dir="auto"
  ...
/>
```

### Voice interim preview

Same treatment — add `dir="auto"` to the `<p>` that shows `{interimText}`:

```tsx
<p dir="auto" className="mt-1 text-xs italic text-gray-400">{interimText}…</p>
```

### Decision: `dir="auto"` vs JS-driven class toggle

| Approach | Pros | Cons |
|----------|------|------|
| `dir="auto"` (chosen) | Zero JS, spec-compliant, works immediately on first keystroke | Font stack applies even for English text |
| JS class toggle | Precise font switching | Requires character detection, extra state, more complexity |

**Decision:** `dir="auto"` — simplest correct approach.

## Part 2 — Session Report Answer Replay (`report-accordion.tsx`)

The report accordion shows each question + the user's answer at line 86:
```tsx
<p className="rounded-md bg-gray-50 px-3 py-2 text-sm text-gray-700">
  {answer.answer_text}
</p>
```
Add `dir="auto"` to this `<p>` so Urdu answers render RTL.

## Part 3 — Font (`globals.css`)

Load **Noto Nastaliq Urdu** from Google Fonts. Nastaliq is the traditional Urdu script style used in Pakistani publishing. Fall back to system Arabic fonts.

**Loading strategy:** Use `next/font/google` if Noto Nastaliq Urdu is in Next.js's supported font list (self-hosted, no runtime external request, better CLS). If not supported, fall back to `@import url(...)` in `globals.css`.

Apply via targeted CSS selectors — not the broad `[dir="auto"]`:

```css
textarea[dir="auto"],
p[dir="auto"] {
  font-family: 'Noto Nastaliq Urdu', 'Noto Naskh Arabic', system-ui, sans-serif;
}
```

> Note: Noto Nastaliq has no Latin glyphs — the browser falls through to `system-ui` for English characters, so English text in `dir="auto"` elements renders correctly.

---

## Part 4 — `<html lang>` attribute

The root layout has `<html lang="en">`. This stays as `"en"` — the app UI is English. Individual RTL surfaces use `dir="auto"` which is independent of the document language.

No change to `src/app/layout.tsx`.

## Acceptance Criteria

```
WHEN user types Urdu text in the answer textarea
THEN the textarea SHALL display text right-to-left, right-aligned

WHEN user dictates Urdu via voice
THEN the interim preview text SHALL display right-to-left, right-aligned

WHEN user views the session report
THEN any Urdu answer in the accordion SHALL display right-to-left, right-aligned

WHEN user types English in the answer textarea
THEN the textarea SHALL continue to display left-to-right, left-aligned (unchanged)

WHEN Urdu text is rendered
THEN the font SHALL be Noto Nastaliq Urdu (or Arabic system fallback)
```
